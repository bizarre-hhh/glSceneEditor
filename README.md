# glSceneEditor

基于 C++20、Qt Widgets 和 OpenGL 3.3 的 STL 场景编辑器。Qt 主窗口提供菜单、工具栏、模型列表和信息面板，中心区域嵌入 GLFW/OpenGL 视口，场景设置使用 Dear ImGui 绘制。

程序启动时先显示欢迎界面，选择“新建工程”或“打开工程”后进入最大化编辑窗口。支持同时加载多个 STL 模型，进行选择、显示或隐藏、包围盒查看和 XY 平移；场景可保存为单个 `.glproj` 工程文件。

## 构建与运行

### 环境要求

- Windows，支持 C++20 的 Visual Studio / MSVC C++ 工具链。
- CMake 3.21 或更新版本（使用版本 3 的 CMake Presets），以及 Ninja。
- 与编译器及目标架构匹配的 Qt 5 或 Qt 6 Widgets 开发套件。
- 支持 OpenGL 3.3 的显卡驱动。

当前预设使用 x64 Qt 套件 `D:/Qt/Qt5.14.2/5.14.2/msvc2017_64`，仓库中的 Assimp 预编译库也为 x64，建议使用 `x64-debug` 或 `x64-release`。

### Debug 构建

在已初始化 **x64 MSVC 编译环境** 的 Visual Studio Developer PowerShell 中运行，确保 `cl`、`cmake` 和 `ninja` 可用：

```powershell
git clone https://github.com/bizarre-hhh/glSceneEditor.git
cd glSceneEditor

cmake --preset x64-debug
cmake --build out/build/x64-debug
.\out\build\x64-debug\glSceneEditor\glSceneEditor.exe
```

如果 Qt 安装在其他位置，可修改 `CMakePresets.json` 中的 `CMAKE_PREFIX_PATH`，或在配置时覆盖该值。下面命令中的路径需要替换成实际 Qt 套件目录：

```powershell
cmake --preset x64-debug -DCMAKE_PREFIX_PATH="C:/Qt/你的Qt版本/你的MSVC套件"
```

### Release 构建

```powershell
cmake --preset x64-release
cmake --build out/build/x64-release
.\out\build\x64-release\glSceneEditor\glSceneEditor.exe
```

预设中还保留了 `x86-debug` 和 `x86-release`。使用它们前，需要配置 x86 编译环境，并提供匹配的 32 位 Qt 套件、Assimp 导入库和 DLL；当前仓库的 x64 依赖不能直接用于 x86 构建。

构建后会将着色器复制到可执行文件旁的 `resources/shaders/`，并复制 Assimp DLL。找到 `windeployqt` 时，还会自动部署 Qt 运行库。运行或复制程序时，需要保留这些资源和运行库，不能只复制 `.exe` 文件。

## 工程管理

启动后的欢迎界面提供“新建工程”和“打开工程”。取消打开文件会留在欢迎界面；关闭欢迎界面或点击“退出”会退出程序。只有选择新建或成功恢复工程后，才会进入场景编辑器。欢迎界面和编辑器中的“打开工程”都默认打开 `D:\vs_cmake_proj\glSceneEditor\glproj` 文件夹。

欢迎窗口还会显示最多 5 个最近打开的工程，最近打开的位于最上方。每项显示文件名和路径，单击即可直接打开，也支持选中后按 Enter。成功进入编辑器或在编辑器内成功打开工程后，更新 `D:\vs_cmake_proj\glSceneEditor\asset\recent_projects.json`；重复工程会移到最上方。打开失败或取消不会更新记录。工程已被移动或删除时，点击后会提示错误并留在欢迎界面。最近工程记录独立于 `.glproj`，不影响工程的未保存状态。

工具栏按钮使用“图标在上、文字在下”的布局，图标为 32 × 32 逻辑像素的 Lucide SVG。图标源文件、来源说明和许可证保存在 `asset/icon/`，通过 Qt 资源系统嵌入程序；替换 SVG 后重新构建即可更新，运行时不依赖工作目录。

编辑器的“文件”菜单和工具栏提供以下操作：

| 操作 | 快捷键 | 行为 |
| --- | --- | --- |
| 新建工程 | `Ctrl+N` | 清空场景、模型选择和当前工程路径，恢复默认背景、视角和显示设置。 |
| 打开工程 | `Ctrl+O` | 打开 `.glproj` 文件并恢复模型及其变换，使用 Home 视角，显示全部模型并关闭包围盒。 |
| 保存工程 | `Ctrl+S` | 有新增操作记录时保存到当前工程文件；没有新增记录时不重复写入。未命名工程首次保存时选择文件名和位置，默认目录为 `D:\vs_cmake_proj\glSceneEditor\glproj`。 |
| 工程另存为 | `Ctrl+Shift+S` | 默认打开 `D:\vs_cmake_proj\glSceneEditor\glproj` 并保留当前文件名；保存到另一个工程文件，并将新文件作为后续“保存”的目标。 |
| 导入 STL 模型 | `Ctrl+I` | 将一个或多个 STL 模型追加到当前工程。 |

自最近一次成功保存后，新增导入、删除、移动、旋转、缩放、修改平台尺寸、撤销或回撤的操作记录时，窗口标题显示 `*`。是否需要保存以新增操作记录为准；即使撤销后模型回到已保存时的位置，仍需保存。新建、打开其他工程或退出前，会提示“保存 / 不保存 / 取消”；取消操作或取消保存文件对话框会保留当前工程。相机视角、模型可见性、选择、包围盒、背景颜色和线框模式属于临时显示设置，调整这些设置不会标记工程修改。

### 工程文件

`.glproj` 是带格式标识和版本号的单个二进制文件，其中嵌入每个模型加载时的 **完整 STL 内容**，并记录原始路径、独立模型实例、XYZ 位移、缩放和旋转。工程文件保存模型及其变换、各实例的初始放置中心和平台尺寸。打开工程后，相机恢复默认 Home 透视视角并按场景范围取景；所有模型显示，包围盒关闭，模型未选中，背景和线框模式恢复默认设置。

因此，移动工程文件、移动或删除原始 STL 文件，都不会影响工程恢复；同一 STL 导入多次时，各实例的位置和变换分别保存。模型信息面板显示原始来源路径及嵌入数据的文件大小。修改原始 STL 不会改变已经保存的工程内容。

保存使用临时文件和原子替换，写入失败时保留原工程文件。打开时先校验文件格式与参数，再在临时场景中加载全部模型；文件损坏、不兼容或模型恢复失败时，当前场景保持原状。当前保存格式为版本 3，兼容读取版本 1 和 2 工程；旧工程的基板尺寸默认为 100 × 100 mm。读取旧工程时保留模型和变换，并使用上述默认显示设置。支持空工程，单个 STL 文件大小上限为 512 MB。

## 加载和管理模型

通过工具栏的“打开 STL”、菜单“文件 → 导入 STL 模型”或 `Ctrl+I` 打开文件对话框，可一次选择多个文件，也可重复导入同一文件。新模型追加到已有场景；部分文件加载失败时，已加载的模型和其他成功导入的模型会保留。

文件对话框当前默认打开 `D:\vs_cmake_proj\glSceneEditor\asset`。在其他目录使用项目时，可修改 [scene_editor_window.cpp](glSceneEditor/scene_editor_window.cpp) 中 `OpenStl()` 的 `initial_directory`。

STL 坐标按毫米、Z 轴向上解释。每个模型加载后在基板的 X/Y 方向居中，最低 Z 点落在基板上。多个模型可能重叠，可选中后拖动调整位置。添加、隐藏和删除模型不会自动改变相机视角；需要重新取景时使用 Home 或“重置视角”。

左侧“STL 模型”窗口列出所有已加载模型。**点击列表行或模型名称不会选择模型**，列表中通过对应按钮操作：

| 按钮 | 功能 |
| --- | --- |
| 选中 / 取消选中 | 切换该模型的选择状态。支持同时选中多个模型，与视口中的选择同步。 |
| 隐藏 / 显示 | 切换模型可见性。隐藏后仍保留模型和选择状态，隐藏模型不能在视口中被拾取。 |
| 显示包围盒 / 隐藏包围盒 | 切换世界坐标包围盒的蓝色线框，默认关闭。被模型或基板遮挡的线段不显示，平移、旋转、缩放时同步更新，即使包围盒隐藏也更新其数据，再次显示使用最新尺寸。隐藏模型时包围盒也隐藏，再显示模型时保留原开关状态。 |
| 删除 | 从场景和列表中移除模型，并释放图形资源，不删除原始 STL 文件。 |

模型窗口可调整宽度、关闭或移动到右侧；拖动列表与信息区之间的分隔条可调整高度。“视图”菜单可重新显示模型窗口和工具栏。

### 模型信息

只有模型被选中时才显示信息。多选时显示最近选中的模型；取消该模型的选择或删除它后，显示其余已选模型中的最近一项。没有选中模型时，信息区清空。

| 区域 | 内容 |
| --- | --- |
| 基本信息 | 文件名、完整路径、文件大小、三角面数和当前世界坐标包围盒的 X/Y/Z 尺寸（mm）；尺寸随变换实时更新，与包围盒显示开关无关。 |
| 包围盒位置 | 世界坐标下的包围盒中心、最小位置和最大位置，分别显示 X/Y/Z 数值（mm）。 |
| 自身变换 | 相对加载后初始姿态的 X/Y/Z 位移（mm）、缩放（倍）和旋转（°）。初始位移和旋转为 0，缩放为 1。 |

“自身变换”各行提供 **平移 / 缩放 / 旋转** 按钮，打开对应参数窗口并切换视图中的 gizmo。窗口可与 OpenGL 视图同时操作，X/Y/Z 参数分别使用毫米、倍数和角度；点击“应用”执行一次变换，“关闭”会丢弃尚未应用的输入。拖动 gizmo 后参数和模型信息实时同步。参数窗口打开期间，所有模型的选中状态锁定，列表中的选择按钮和视图点选均不可修改选择；关闭窗口后恢复。

Gizmo 使用模型局部坐标轴：平移可拖动轴、平面和中心；旋转可拖动圆环；缩放可沿单轴或从中心整体缩放。旋转和缩放均绕当前模型中心进行。位移参数保留旧工程的局部坐标约定，改变旋转时会换算位移以保持模型中心不动。缩放倍数必须大于 0。选中模型时不显示 gizmo；只有打开对应参数窗口才显示对应操纵器，关闭窗口即隐藏。切换变换按钮会同步切换窗口和操纵器。信息数值仍可复制。

## 撤销、回撤和操作记录

工具栏和“编辑”菜单提供“撤销”“回撤”和“操作记录”：

| 操作 | 快捷键 | 行为 |
| --- | --- | --- |
| 撤销 | `Ctrl+Z` | 撤销上一步成功打开 STL、删除 STL、移动、旋转、缩放模型或修改平台尺寸的操作。 |
| 回撤（重做） | `Ctrl+Y` 或 `Ctrl+Shift+Z` | 重新执行上一步被撤销的操作。 |
| 操作记录 | — | 打开独立窗口，按最近操作在上方的顺序显示每一步操作。 |

每个成功导入的 STL 文件记录为一步；删除模型记录为一步；按下鼠标并拖动模型直到松开，整个拖动过程只记录为一步；gizmo 的平移、旋转、缩放拖动同样合并为一步。每次成功应用变换参数或确认修改平台尺寸记录为一步。未移动的点击、拖回原位置、失败的导入或移动、取消尺寸窗口或确认未变更的尺寸不会增加记录。移动记录包含文件名及移动前后的 XYZ 位移（mm）。选择、隐藏/显示、包围盒和相机调整属于临时显示操作，不进入撤销记录。

撤销删除会恢复模型的位置、列表顺序及删除时的选择、显示和包围盒状态。撤销与回撤使用缓存的 STL 内容，原始文件移动或删除后仍可恢复模型。操作记录也会列出执行的撤销和回撤；窗口保持打开时会跟随操作更新，关闭后可以再次打开。

没有可撤销或可回撤的步骤时，对应按钮禁用。撤销后执行新的导入、删除或移动操作，会清除原来的重做步骤；撤销和回撤产生的新记录也会使工程需要保存。成功保存或另存为后，将当前记录位置标记为已保存，保留当前会话的记录；取消或保存失败不会更新已保存位置。新建或打开工程会清空撤销、回撤和操作记录。操作记录属于当前编辑会话，不写入 `.glproj` 文件。

## 视口操作

以下鼠标和键盘操作在 OpenGL 视口中使用：

| 操作 | 效果 |
| --- | --- |
| 左键点击模型 | 选中模型，橙色高亮，并突出显示对应列表行。不会取消其他模型的选择；重叠处拾取离相机最近的可见模型。 |
| 在已选中模型上按住左键拖动 | 移动被拖动的模型，其他模型保持原位。只改变世界 X/Y，Z 值固定；可拖出基板范围。第一次点击未选中的模型只负责选中。 |
| 左键点击空白区域 | 取消所有模型的选择并清空信息区。 |
| 右键拖动 | 围绕当前观察中心旋转相机，视角立方体同步旋转。 |
| 中键拖动 | 平移视图。 |
| 鼠标滚轮 | 调整观察距离。 |
| Home 键 | 恢复默认透视视角，并按当前场景范围重新取景。 |

松开左键结束模型拖动；隐藏、删除或取消选中正在拖动的模型也会结束拖动。移动模型不会修改原始 STL 文件。

### 视角立方体与 Home

视口左下角的立方体实时显示相机方向。左键点击 Front、Back、Left、Right、Top、Bottom 面，切换到前、后、左、右、上、下标准视图，保留当前观察中心、距离和模型选择。六个标准视图均使用正交投影：

- 前、后视图显示 X 和 Z 轴。
- 左、右视图显示 Y 和 Z 轴。
- 上、下视图显示 X 和 Y 轴。

沿视线方向的坐标轴及其标记会隐藏。立方体的面有悬浮高亮，不显示提示气泡；在立方体上按住右键也可拖动旋转视角，拖出立方体后仍可继续，松开右键结束。

立方体下方的 Home 按钮、工具栏及菜单中的“重置视角”和 Home 键使用相同的默认视角。重置时根据基板、坐标轴和所有已加载模型（包括隐藏模型）重新取景，将场景放大并向上调整布局，同时保留模型选择。

### 场景设置与投影

通过工具栏或“视图 → 场景设置”打开设置面板，可调整线框模式、背景颜色和相机参数。

`Projection` 下拉框实时显示当前投影模式，可选择 `Perspective`（透视）或 `Orthographic`（正交）。手动切换投影时，保留相机方向、观察中心、距离和模型状态。

点击立方体的标准视图面会切换为正交投影；中键平移和滚轮缩放保持当前投影模式。右键旋转、编辑相机 Yaw/Pitch 或 Home 重置会恢复透视投影，下拉框同步更新。

## 坐标与基板

- 1 个场景单位对应 10 mm，STL 文件中的数值按毫米解释。
- 基板默认为 100 mm × 100 mm 的水平平面。工具栏或“视图”菜单的“平台尺寸”可修改长度（X）和宽度（Y），范围为 1～10000 mm，支持两位小数；确认后更新基板、网格、坐标轴并按新尺寸使用 Home 取景。网格间距为 10 mm，边缘刻度间距为 5 mm。
- 修改尺寸保持已有模型的世界位置；后续导入模型放在当前平台中心。尺寸随工程保存，可撤销和回撤；新建工程恢复默认尺寸。
- 基板一角为原点 `(0, 0, 0)`，X/Y 轴沿基板两条边，Z 轴垂直向上。
- X、Y、Z 轴分别为红、绿、蓝色，长度随平台更新：X/Y 轴分别为平台长/宽的 1.2 倍，Z 轴为长宽较大值的 1.2 倍；默认均为 120 mm，末端显示箭头和字母标记。
- 基板为零厚度平面，从上方看不透明，从下方看为 50% 半透明。

## 依赖

GLFW、Dear ImGui、GLAD、GLM、Assimp 和 stb_image 的项目所需文件保存在 `3rd_party/` 中。GLFW 管理渲染窗口和输入，Dear ImGui 使用 GLFW / OpenGL 3 后端绘制场景设置，GLAD 加载 OpenGL 函数，GLM 提供数学运算，Assimp 导入模型。Qt 开发套件和 MSVC 工具链需要另行安装。

当前构建使用仓库中的 Windows Assimp 预编译库，因此项目的构建配置面向 Windows。

## 验证工程功能

默认启用 CTest 测试。构建后运行：

```powershell
ctest --test-dir out/build/x64-debug --output-on-failure
```

`project_roundtrip` 验证工程读写、中文路径、重复模型实例、删除原始 STL 后恢复、世界坐标一致性、Home 视角、默认显示状态、旧格式兼容、空工程及损坏文件保护，以及导入/删除/移动的撤销与回撤、拖动合并和分支切换，以及平台尺寸变更、模型位置保持、尺寸边界和新版工程兼容；还验证三种模型变换、中心保持、欧拉角转换、真实 gizmo 鼠标拖动、拖动合并、完整姿态撤销和工程恢复；`project_ui_workflow` 验证工程菜单、快捷键、默认打开目录、首次保存、另存为、平台尺寸窗口的确认与取消、模型变换按钮和非模态参数窗口、数值应用及关闭、撤销回撤后的字段同步、未保存修改的取消和放弃流程，以及重新打开当前工程时的保存行为、按新增操作记录判断保存状态、无新增记录时跳过文件写入、工具栏按钮和操作记录窗口顺序，以及最近工程记录的持久化、去重、五项上限、单击打开和失效工程提示。测试使用临时目录保存最近工程记录，不修改实际记录；界面测试使用隐藏窗口，需要与主程序相同的 OpenGL 3.3 环境。只构建主程序时可在配置阶段使用 `-DBUILD_TESTING=OFF`。

模型 gizmo 使用 [ImGuizmo](https://github.com/CedricGuillemet/ImGuizmo)，固定源码版本及许可证位于 `3rd_party/ImGuizmo`。
